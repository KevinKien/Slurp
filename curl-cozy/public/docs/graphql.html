GraphQL

Explore a GraphQL schema, build operations from it and send them. Open GraphQL in the sidebar, or right-click a request in HTTP History and choose Open in GraphQL to start from a captured request: its endpoint, headers, query, variables and operation name fill the editor. Requests are sent through the same backend as Replay, so the same target restrictions apply (HTTP(S) only, DNS pinning, no automatic redirects, bounded responses and timeouts).

Load the schema

Enter the endpoint, put any authentication under Headers (one Name: value per line) and choose Load schema. Slurp sends the standard introspection query and builds the schema explorer from the answer. The schema stays loaded while you move between pages and is not saved to disk.

When the server has introspection disabled, the error is shown and the editor stays usable. Use Import schema to load a schema you saved elsewhere: the JSON result of an introspection query, as {"data":{"__schema":…}}, {"__schema":…} or the __schema object itself. Schema definition language (SDL) files cannot be imported.

Schema explorer

  • Tabs list the queries, mutations and subscriptions of the schema, and all types.
  • Each field shows its arguments, return type, description and deprecation. Type names are links: open an object, interface, input, enum or union to see its fields, values or members, and use Back to return.
  • Search matches type, field, argument and enum-value names across the whole schema.
  • Copy SDL copies the loaded schema as schema definition language.

Build an operation

Choose Use beside a root field. Slurp writes a ready-to-send operation: required arguments become variables with sample values (empty strings, zero, the first enum value, input objects with their required fields), optional arguments are left out, and the selection set lists scalar and enum fields plus nested objects two levels deep. A type already on the path is not expanded again, so cycles such as User.friends are cut. Fields that need arguments and deprecated fields are not selected. Unions select __typename and the first six members. Edit the result freely.

Edit and send

  • The editor has Query, Variables (a JSON object) and Headers tabs. Prettify re-indents the query and the variables. Ctrl/⌘+Enter in the query sends.
  • The request is a JSON POST with query, variables and operationName. The operation name is taken from the query when it contains exactly one named operation, or from the field you fill in. Content-Type is set to application/json; Host, Content-Length and similar connection headers are never copied.
  • The response shows the status, time and size, the JSON pretty-printed, and any GraphQL errors above it. A second tab shows the response headers.
  • Send to Replay opens the request as a new Replay tab; Copy cURL copies it as a command.

Limits

Requests that arrive as GraphQL over GET, batched arrays or application/graphql bodies can be opened (the first operation is used) but are sent as a single JSON POST. The editor does not validate queries or autocomplete from the schema: the server's own errors are shown. Subscriptions are listed but cannot be run, and file uploads (multipart) are not supported. Security checks for GraphQL (introspection exposure, field suggestions, batching) are described in Scan dashboard.
