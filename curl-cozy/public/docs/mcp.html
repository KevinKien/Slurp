Connect an AI client to Slurp

Set up Claude Code, Claude Desktop, Codex, DeepSeek Harness, OpenCode or Google Antigravity to search captured traffic and work with Replay requests.

Before you start · Claude · Codex · DeepSeek Harness · OpenCode · Antigravity · Authentication · Troubleshooting

Before you start

  1. Install the latest Slurp binary for your OS and CPU. Add its directory to the PATH used by your AI client, or replace slurp in the examples with the actual absolute executable path. Use slurp.exe on Windows.
  2. Start Slurp in a separate terminal with slurp, or open Slurp.app on macOS. Keep it running. The default API address is http://127.0.0.1:5174.
  3. Open the startup URL to access the UI, select a workspace or temporary session, and capture some requests.
  4. Configure your AI client below, then restart or reload its MCP connections.

The connection is AI client → local slurp mcp process over stdio → running Slurp REST API. The client starts the MCP process for you. Starting slurp mcp does not start the proxy backend.

Choose a local/stdio MCP server. Slurp does not expose a Streamable HTTP or SSE MCP endpoint. Do not enter http://127.0.0.1:5174, /api/ws or the browser startup URL as a remote MCP server URL. Port 8888 is the interception proxy, not the API.

For JSON configuration, use an executable path without shell quote characters inside the value. Windows paths require escaped backslashes, for example "C:\\Tools\\Slurp\\slurp.exe". A GUI client may have a different PATH from your terminal; an absolute executable path avoids that difference. Merge examples into existing configuration instead of replacing unrelated servers.

Claude Code

Add the stdio server from your terminal:

claude mcp add --transport stdio slurp -- slurp mcp
claude mcp list

The default scope is local to the current project. Add --scope user before the server name if you want it available across projects:

claude mcp add --transport stdio --scope user slurp -- slurp mcp

Open Claude Code and use /mcp to inspect the server status and approve it if prompted. If a server named slurp already exists, update its executable path or remove that entry before adding a replacement.

Claude Desktop

Open the desktop application's developer settings and edit its MCP configuration. Add this entry to its mcpServers object, then restart the application:

{
  "mcpServers": {
    "slurp": {
      "command": "slurp",
      "args": ["mcp"]
    }
  }
}

Use a local desktop configuration. A hosted web connector that only accepts remote MCP URLs cannot launch Slurp's stdio process.

Reference: Claude Code MCP documentation.

Codex

Register the server with the Codex CLI:

codex mcp add slurp -- slurp mcp
codex mcp list

Alternatively, merge this table into ~/.codex/config.toml. A trusted project can use .codex/config.toml:

[mcp_servers.slurp]
command = "slurp"
args = ["mcp"]

Restart or reload Codex's MCP connections after changing configuration. In the Codex terminal UI, use /mcp to check the server. Slurp does not use MCP OAuth; codex mcp login slurp is not needed for this stdio connection.

Reference: Official OpenAI documentation for Codex MCP.

DeepSeek Harness (DSH)

DeepSeek Harness uses Cordis plugin configuration. Create a file named slurp.cordis.yml with this overlay:

- insert:
    - id: mcp-slurp
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: slurp
        transport: stdio
        command: slurp
        args: [mcp]

From the directory containing that file, start DSH with the overlay:

dsh web --patch ./slurp.cordis.yml

For a persistent setup, merge the insert patch into $DSH_HOME/cordis.patch.yml or the appropriate profile's cordis.patch.yml. Keep the server name and plugin ID unique in that scope. Tools appear with names such as mcp__slurp__search_history.

DSH scrubs credential-like environment variables before starting stdio children. Local Slurp token-file discovery still works when the child uses the same home directory. If you rely on an environment token, explicitly forward it in the entry's config.env:

        env:
          SLURP_API_TOKEN: !!js process.env.SLURP_API_TOKEN

References: DeepSeek Harness MCP client and DSH overlay setup examples.

OpenCode

Merge this local MCP entry into the project's opencode.json or opencode.jsonc:

{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "slurp": {
      "type": "local",
      "command": ["slurp", "mcp"],
      "enabled": true
    }
  }
}

Restart OpenCode after saving and check its MCP server status. The command is an array: executable first, followed by each argument. Do not use the mcpServers shape from Claude Desktop here. Optional child-process environment variables belong in this entry's environment object.

Reference: OpenCode MCP servers documentation.

Google Antigravity

In the editor's agent side panel, open … → MCP Servers → Manage MCP Servers → View raw config. Merge this stdio entry into the configuration the editor opens:

{
  "mcpServers": {
    "slurp": {
      "command": "slurp",
      "args": ["mcp"]
    }
  }
}

Save, refresh MCP servers, and enable Slurp. Use the file opened by your installed version; current documentation describes ~/.gemini/config/mcp_config.json for global configuration and .agents/mcp_config.json for workspace configuration. The Antigravity CLI also provides a /mcp manager. Use command and args for Slurp rather than a remote serverUrl.

Reference: Antigravity MCP documentation.

Authentication and a different API port

Every MCP API call requires the management token. When the MCP process and backend run as the same OS user on the same machine, Slurp reads it automatically from ~/.slurp/api-token on macOS/Linux or %USERPROFILE%\.slurp\api-token on Windows. No token needs to be pasted into the client configuration. Start the backend first so the file exists.

SLURP_API_TOKEN, when supplied to the MCP child process, takes precedence over the token file. Use the backend's raw 64-character token, without Bearer or the startup URL. Restart the MCP process after changing its token or environment. The AI provider's API key is a separate credential.

For a non-default API address, keep stdio and change the child-process arguments. For example:

slurp mcp --api http://127.0.0.1:15174

In clients with a separate args field, use:

["mcp", "--api", "http://127.0.0.1:15174"]

In OpenCode's command array, use ["slurp", "mcp", "--api", "http://127.0.0.1:15174"]. The API address must match Slurp's UI/API listener, not its proxy listener. Without --api, the CLI also honors SLURP_API_ADDR.

For a backend on another machine, prefer an SSH tunnel to its loopback API, forward a local port such as 15174, and give the local MCP process that backend's token through SLURP_API_TOKEN. Do not send the token over an unencrypted network connection. Keep tokens out of prompts and version-controlled project files.

Verify the connection

Ask the assistant to use Slurp's list_workspaces, then get_stats or search_history. For traffic captured without a saved workspace, pass workspace: "temporary"; temporary traffic is lost when Slurp stops.

Use Slurp to list workspaces. Then search the temporary history for failed requests and summarize the results without sending any requests.

Slurp also exposes get_traffic, list_traffic, list_replay, create_replay, edit_replay, rename_replay, send_replay and clear_traffic. Captured credentials and bodies become accessible to the connected assistant. send_replay sends a real HTTP request; clear_traffic deletes captured history. Use the client's tool approval controls accordingly.

Troubleshooting

SymptomWhat to check
Executable not found / ENOENTCheck the client's PATH or use the actual absolute path to the latest Slurp executable. A shell cd does not change a GUI client's PATH. On Windows, use slurp.exe and valid JSON path escaping.
Connection refusedStart the Slurp backend and check its printed API address. slurp mcp alone does not start it. Match the API port in --api.
API returned 401 UnauthorizedCheck that the MCP child uses the same OS user/home as the backend. Remove an outdated SLURP_API_TOKEN override or update it to the correct backend token, then restart the MCP connection.
No tools / invalid protocol responseConfigure local stdio with the mcp argument, not a URL or the regular Slurp startup command. Avoid shell wrappers that print banners to stdout. Check the client's MCP logs.
No matching historyCapture traffic first and check the workspace filter. Use temporary for in-memory traffic. list_workspaces lists saved workspaces, not the temporary session.
Old behavior after an updateUpdate the executable path in the MCP configuration and restart its child process. Existing clients can keep an older executable running after a new binary has been built.
Web UI says Proxy offlineThe UI's WebSocket status is separate from MCP stdio. Check the running binary version, open the authenticated startup URL and reload the UI. Test an MCP read tool separately.
