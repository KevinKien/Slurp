Replay Scripts: After response

Scripts extract data from a response and save it as variables for subsequent requests. Each Replay tab has its own script. With no authentication profile selected, variables are shared across tabs in the same workspace. With a profile selected, scripts read shared variables plus profile overrides and save updates to that profile only. See Account Profiles for per-account token and cookie setup.

Quick start: save an access token

  1. Open the login request for user A and select Scripts.
  2. Enter the script below and click Send. Adjust body.data.access_token to match your API's JSON response.
const body = response.json();

if (response.status === 200) {
  const token = body.data?.access_token;
  if (typeof token !== "string" || !token) {
    throw new Error("Response does not contain an access token");
  }
  variables.set("token1", token);
  console.log("Updated token1");
}

In the login tab for user B, use the same script and replace token1 with token2. Open Variables to inspect the saved values.

In the Headers tab of a request that requires authentication, add:

Authorization: Bearer {{token1}}

Use {{token2}} to send as user B. The {{variable_name}} syntax works in URLs, headers, and request bodies. Variables are updated after the response, so their new values apply to subsequent sends.

Available APIs

APIDescription
response.statusThe numeric HTTP status code, such as 200 or 401.
response.json()Parses the response body as JSON. Throws if the body is not valid JSON.
response.text()Returns the response body as a string.
response.headersAn object containing response headers. For example, response.headers["content-type"]. See the example below for a case-insensitive header lookup.
variables.get("token1")Returns the string value, or undefined if the variable does not exist. Also reads changes made earlier in the same script.
variables.set("token1", value)Sets a variable. Both the name and value must be strings. Use String(value) for numbers or JSON.stringify(value) for objects.
console.log/info/warn/error(...args)Writes logs shown under After response. log(...args) is an alias for console.log.

More examples

Save a numeric ID and an object from a JSON response:

const body = response.json();
variables.set("user_id", String(body.user.id));
variables.set("user", JSON.stringify(body.user));

Read a response header regardless of its capitalization:

const entry = Object.entries(response.headers)
  .find(([name]) => name.toLowerCase() === "x-request-id");
if (entry) variables.set("request_id", entry[1]);

Execution, logs, and errors

  • Scripts run after clicking Send in the web UI and receiving a response, including HTTP 4xx/5xx responses. If a request fails without a response, the script is skipped. Sending through MCP does not currently execute scripts.
  • Variable changes are applied only when the entire script succeeds. If it throws or exceeds a limit, existing variables are preserved. The HTTP response remains available to inspect.
  • Expand After response in the response pane to view logs, errors, and the names of updated variables. Avoid logging tokens, since logs are stored in send history.
  • Send history stores the script and its result for each send. Viewing history or restoring a request does not execute the script again.
  • Scripts are saved with their tabs when a workspace is selected. Without a workspace, data stays in the current session and is lost on reload.

Limits

  • Only synchronous JavaScript is supported. Do not use async/await, promises, timers, fetch, DOM APIs, Node.js APIs, or library imports.
  • Scripts are limited to 32,000 characters, approximately 300 ms of execution time, and 16 MiB of memory. The worker is terminated if it does not finish within 3 seconds.
  • Up to 100 variables are supported, with a maximum of 64,000 bytes per value. Names must start with a letter or _, followed by letters, digits, _, ., or -, with a maximum length of 100 characters.
  • Up to 100 log entries are supported, with each entry truncated to 2,000 characters. Logs produced before a script error are not currently retained.
