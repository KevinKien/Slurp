I. Tổng quan thay đổi

Đây là bản mở rộng lớn của Scan engine, thêm 18 kiểm tra bảo mật mới, crawler tự động, hỗ trợ JWT nâng cao, và business logic testing. Thay đổi trải dài cả backend (Rust) và frontend (TypeScript/React).

Engine Cải tiến Scan Engine lõi

Crawler tự động

  • Crawler mới (crawler.ts, 195 dòng) — thu thập cùng-origin links, scripts, GET forms
  • Cấu hình: tối đa 50 URL, depth 0–5, giới hạn Target Scope
  • Tự động tạo ScanEngine con cho mỗi endpoint được crawl
  • Budget giới hạn evidence 8MB cho crawl scan
  • UI hiển thị tiến trình crawl realtime (fetched/queued/URLs)

Form parameter support

  • Thêm loại parameter form cho application/x-www-form-urlencoded
  • Hỗ trợ mutateParameter, parameterValue, isFormRequest
  • Giới hạn checks tăng từ 40 → 64

JWT nâng cao

  • RSA material parser mới (rsa-material.ts, 141 dòng) — parse SPKI/PKCS#1/X.509
  • OAST collector hỗ trợ hosting JWKS và certificates cho jku/x5u attacks
  • User cung cấp RSA public key qua UI (validate, reject private keys)
  • Web Crypto dùng cho local key generation và signing

Business logic testing

  • Tự động phát hiện numeric/date fields (businessKind heuristic)
  • Business read-back verification: GET endpoint xác nhận thay đổi persist
  • JSON pointer cho truy xuất field cụ thể trong response
  • mutateNumber helper giữ đúng kiểu (string vs number) trong JSON

Host header injection

  • Backend mới: send_host() gửi request với Host/X-Forwarded-Host override, pinned to original socket
  • HTTP/1.1 only khi override Host header (tránh HTTP/2 pseudo-header conflict)
  • Strict validation: chỉ slurp-*.invalid hostnames, reject CRLF injection

  • http_target.rs — client_options() hỗ trợ HTTP/1.1 only mode
  • lib.rs — Register 2 module mới + 2 API routes (/api/scan/host-header, /api/scan/oast/keys)

II. Ý tưởng & Kế hoạch thực hiện

Dựa trên trạng thái hiện tại, đây là những hướng phát triển tiếp theo được ưu tiên:

🔴 Ưu tiên cao — Hoàn thiện bản release

1 Chạy toàn bộ test suite và fix failures Quan trọng

Chạy cargo test (backend) và npx vitest run (frontend) để xác nhận mọi thứ pass. Nhiều file thay đổi cùng lúc, cần đảm bảo không có regression. Cũng cần chạy cargo clippy để bắt warning.

2 Cập nhật RELEASE_NOTES.md cho v1.2 Quan trọng

File RELEASE_NOTES.md hiện chỉ chứa nội dung v1.0.1. Cần viết release notes mới bao gồm: 18 scan checks mới, crawler, JWT key-source attacks, business logic testing, form parameter support, host header injection, và CORS trust checks.

3 Cập nhật documentation (/docs/scan.html) Quan trọng

Tài liệu scan cần document: cách dùng crawler, cấu hình business read-back, cung cấp JWT public key, các scan profile mới, và giải thích các check experimental.

4 Commit và tạo version tag Quan trọng

25 file thay đổi chưa commit. Nên chia thành vài commit có ý nghĩa hoặc một commit lớn với message mô tả rõ. Cập nhật version number trong codebase.

🟡 Ưu tiên trung bình — Cải thiện chất lượng

5 Test thủ công end-to-end trên real server Medium

Các check experimental (jwt-confusion, host-header, cors-trust, nosql) cần được test trên ứng dụng thực. Set up một vulnerable test app (DVWA, Juice Shop, hoặc custom) để verify findings.

6 Tăng test coverage cho crawler edge cases Medium

  • Crawl với redirect chains
  • Crawl gặp non-HTML responses (JSON APIs, binary)
  • Crawl timeout và error handling
  • Evidence budget exceeded khi crawl nhiều endpoint
  • Concurrency: crawl child engine bị stop/pause

7 Refactor auto_audit.rs — DRY pattern Medium

start_header_audit() duplicate khá nhiều logic từ worker chính. Xem xét extract generic audit runner pattern dùng trait hoặc closure để giảm code lặp.

8 Scan profiles UX — Auto-detect applicable checks Medium

Hiện user phải chọn profile thủ công. Có thể auto-detect: nếu request có JWT → suggest JWT profiles, nếu JSON body → suggest NoSQL/business checks, nếu có CORS headers → suggest CORS checks.

🟢 Ưu tiên thấp — Tính năng tương lai

9 Scan report export (PDF/HTML) Low

Export findings thành report chuyên nghiệp với severity ratings, evidence screenshots, remediation guidance. Hữu ích cho pentesting reports.

10 Scheduled/recurring scans Low

Cho phép schedule scan định kỳ trên saved requests để phát hiện regression. Cần backend cron job hoặc timer.

11 Scan comparison (diff between runs) Low

So sánh 2 scan runs trên cùng endpoint để phát hiện findings mới/đã fix. Hữu ích sau khi dev fix vulnerability.

12 SSRF và blind injection improvements Low

Mở rộng OAST checks cho: blind SSRF qua redirect chains, blind SQL injection qua DNS exfiltration, SMTP header injection.

13 WebSocket scan support Low

Scan engine hiện chỉ hỗ trợ HTTP. WebSocket messages cũng có thể chứa injection vectors, authorization bypass, v.v.
